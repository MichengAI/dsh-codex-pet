# 多会话通知与交互验收

更新时间：2026-09-09 14:29（Asia/Shanghai）

## 范围与行为

原版对照来自本机 Codex 26.901.6511.0 的 avatar-overlay-native-page 模块，仅核对行为，没有移植代码。对齐多会话通知列表、收起与展开、数量、状态优先和最新优先排序、按轮次关闭和恢复、打开对应会话、审批、结构化问题与计划回答、通知跳转。停止按钮调用目标 session.cancel，只停止当前轮，宿主排队消息仍可能继续。

通知从全部列表会话聚合，不用当前会话单独覆盖其余通知。完成通知跨会话切换保留，历史 replace 不冒充完成，aborted 不报成功。等待、失败、完成、运行默认顺序；同级按更新时间。参照原版等待 24 小时、失败 1 小时、完成 7 天过期，运行无时间过期。关闭通知不批准、不停止请求；新轮次或新交互键重新出现。关闭及排序设置保留于当前客户端生命周期，重新加载后从宿主重建。

审批使用当前 PendingApproval.answer(allowed-once/rejected)，问题与计划使用 PendingQuestion.answer({answers})。按原问题 ID 和选项原文提交，校验单选、多选、文本、漏答、过期身份及重复提交；未知请求仅提供打开会话入口。工具详细参数以会话为准，宠物显示宿主提供的工具名和审批理由。

## 双端

Web 和原生窗共用 NotificationTray。Desktop 新增通知数据校验及请求/结果回传 IPC，来源身份、通知 token 和 requestKey 双重核对，失败返回 UI，15 秒无响应超时提示。新版桥接 notificationsVersion=2；旧 Desktop 自动使用网页内多会话组件，避免静默丢掉通知。相邻 Desktop 源码已构建，本轮没有替换正常安装包。

## 交付与恢复

插件 lib 和 tgz 已重建，正常 profile 链接本工作区。刷新 DSH 加载客户端；如果仍使用旧缓存，空闲时重启 Desktop。桌面原生新版桥接需安装包含本轮源码的 Desktop。

相邻 Desktop 修改限 4 个 pet/preload 实现文件及策略测试，未提交、未推送。恢复时保留用户配置和宠物资源，只回退本轮通知与桥接代码；旧桥接使用网页回退。
